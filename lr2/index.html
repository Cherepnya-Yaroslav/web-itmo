    Лабораторная работа 2. Потоки, процессы и асинхронность

    Тема и цель

    Работа посвящена сравнению трёх моделей конкурентного выполнения в Python: threading, multiprocessing и asyncio.

    Реализованы две задачи:

    1. подсчёт суммы чисел от 1 до 10000000000000;
    2. параллельная загрузка HTML-страниц, извлечение <title> и сохранение результата в PostgreSQL.

    Для каждой задачи сделаны три отдельные программы. Каждая программа разбивает работу на подзадачи, запускает их выбранным способом, замеряет время и печатает результат.

    Структура файлов

    Файл Назначение
    sum_threading.py сумма через ThreadPoolExecutor
    sum_multiprocessing.py сумма через ProcessPoolExecutor
    sum_async.py сумма через asyncio.to_thread и gather
    sum_common.py диапазоны, формула суммы, эталонный результат
    parse_threading.py парсинг через потоки
    parse_multiprocessing.py парсинг через процессы
    parse_async.py парсинг через asyncio и aiohttp
    parser_common.py HTTP-загрузка, <title>, SQLAlchemy-модель и запись в БД
    requirements.txt aiohttp, psycopg, SQLAlchemy

    Задача 1. Подсчёт суммы

    Константа MAX_NUMBER находится в sum_common.py и равна 10_000_000_000_000.

    Функция build_ranges() делит диапазон на части по числу исполнителей. Функция sum_range() не перебирает числа по одному, а использует формулу арифметической прогрессии:

    (start + end) * count / 2

    Это позволяет получить результат быстро и при этом сохранить требуемую идею разбиения задачи на параллельные подзадачи.

    Во всех трёх файлах есть функция calculate_sum():

    • threading создаёт ThreadPoolExecutor;
    • multiprocessing создаёт ProcessPoolExecutor;
    • async создаёт задачи asyncio.to_thread() и ждёт их через asyncio.gather().

    Ожидаемый результат:

    50000000000005000000000000

    Задача 2. Парсинг страниц

    Фиксированный список URL находится в parser_common.py:

    https://example.com
https://www.iana.org/domains/reserved
https://fastapi.tiangolo.com
https://docs.sqlalchemy.org
https://www.postgresql.org

    Во всех вариантах есть функция parse_and_save(url).

    parse_threading.py использует ThreadPoolExecutor, parse_multiprocessing.py - ProcessPoolExecutor, parse_async.py - aiohttp.ClientSession, asyncio.gather() и асинхронные функции.

    Общий модуль parser_common.py:

    1. создаёт HTTP-запрос с User-Agent;
    2. загружает HTML с таймаутом;
    3. разбирает тег <title> через HTMLParser;
    4. формирует ParseResult;
    5. сохраняет его через SQLAlchemy в PostgreSQL;
    6. печатает URL, title, status и длительность.

    Таблица результатов

    Таблица parser_results создаётся автоматически. Поля:

    Поле Назначение
    id идентификатор результата
    url исходный URL
    title найденный заголовок
    status success или error
    error текст ошибки, если запрос не удался
    worker_type threading, multiprocessing или asyncio
    duration_ms время отдельного запроса
    created_at время записи

    Запуск

    Сначала должен работать PostgreSQL из ЛР3:

    cd lab3
docker compose up -d
cd ..

    Затем из корня проекта:

    export DATABASE_URL="postgresql+psycopg://postgres:postgres@localhost:5433/time_manager"
source .venv/bin/activate

python lab2/sum_threading.py
python lab2/sum_multiprocessing.py
python lab2/sum_async.py

python lab2/parse_threading.py
python lab2/parse_multiprocessing.py
python lab2/parse_async.py

    Порт 5433 используется только с хоста. Внутри Docker-сети база доступна как db:5432.

    Теория для защиты

    Threading

    Потоки работают внутри одного процесса. Они удобны для I/O-bound задач: пока один поток ждёт сеть, другой может выполнять работу. Для CPU-bound задач ускорение ограничено GIL.

    Multiprocessing

    Процессы имеют отдельные интерпретаторы Python и память. Поэтому они лучше подходят для CPU-bound вычислений и обходят ограничение GIL, но требуют больше памяти и времени на создание.

    Asyncio

    asyncio использует event loop и переключает задачи в момент ожидания. Это удобно для большого числа сетевых запросов, если библиотека поддерживает async API. В этой работе такой библиотекой является aiohttp.

    Фактический результат

    Все три программы суммы вернули одинаковый эталонный результат. Все три парсера обработали пять URL, вывели заголовки страниц и сохранили результаты в PostgreSQL. На реальном запуске конкретное время зависит от сети, DNS, нагрузки сайтов и компьютера, поэтому сравнивать следует не абсолютные цифры из чужого запуска, а общую характеристику подходов.

    Что показать на защите

    Сначала запустить три команды parse_* в терминале и показать различие названий файлов. Затем открыть parser_common.py и показать общую запись в БД. После этого можно объяснить, что меняется только модель конкурентности, а формат результата и таблица остаются общими.
