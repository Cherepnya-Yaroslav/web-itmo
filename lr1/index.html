    Лабораторная работа 1. FastAPI-приложение

    Тема и цель

    Тема работы - разработка серверного приложения на FastAPI. В качестве предметной области выбран тайм-менеджер. Пользователь может создавать задачи, задавать им описание, статус, приоритет и дедлайн, учитывать фактически затраченное время, распределять задачи по категориям, составлять планы на день и создавать напоминания.

    Цель работы - получить полноценное типизированное серверное приложение с PostgreSQL, ORM-моделями, CRUD API, миграциями Alembic, структурой по слоям и пользовательской аутентификацией.

    Вложенные связанные объекты схемы *DetailedRead и eager loading в services
    Alembic lab1/migrations/ и lab1/alembic.ini
    Типизация аннотации роутеров, сервисов и Pydantic-схем

    Хэширование паролей pwdlib в security.py

    Вход приложения и конфигурация

    app/main.py создаёт объект FastAPI, подключает общий api_router с префиксом /api/v1 и добавляет endpoint /health.

    app/core/config.py описывает настройки через Pydantic Settings:

    • DATABASE_URL - подключение к PostgreSQL;
    • SECRET_KEY - ключ подписи JWT;
    • ACCESS_TOKEN_EXPIRE_MINUTES - срок жизни access token;
    • PARSER_SERVICE_URL - адрес отдельного parser-service;
    • CELERY_BROKER_URL и CELERY_RESULT_BACKEND - адреса Redis для Celery.

    app/db/session.py создаёт SQLAlchemy engine и фабрику сессий. get_db() передаёт сессию в endpoint через dependency injection и гарантированно закрывает её после запроса.

    Модель данных

    В базе восемь предметных таблиц:

    Таблица Модель Назначение
    users User пользователи и хэш пароля
    tasks Task задачи пользователя
    categories Category категории задач
    task_categories TaskCategory связь задачи и категории
    time_entries TimeEntry записи затраченного времени
    daily_plans DailyPlan план пользователя на дату
    daily_plan_tasks DailyPlanTask задачи внутри плана
    reminders Reminder напоминания по задачам

    Файлы моделей:

    • app/models/user.py - пользователь и связи с другими сущностями;
    • app/models/task.py - задача, владелец, категории, время и напоминания;
    • app/models/category.py - категории и TaskCategory;
    • app/models/time_entry.py - интервалы фактически затраченного времени;
    • app/models/daily_plan.py - планы и DailyPlanTask;
    • app/models/reminder.py - напоминания;
    • app/models/__init__.py - экспорт моделей для Alembic.

    Связи one-to-many: User -> Task, User -> DailyPlan, User -> TimeEntry, Task -> TimeEntry, Task -> Reminder. Связи many-to-many: Task <-> Category через TaskCategory и DailyPlan <-> Task через DailyPlanTask.

    Ассоциативные сущности имеют дополнительные поля: importance_weight и is_primary у TaskCategory; planned_minutes, position и is_completed у DailyPlanTask.

    API

    Аутентификация

    Файл: lab1/app/routers/auth.py.

    Метод Endpoint Назначение
    POST /api/v1/auth/register регистрация
    POST /api/v1/auth/login выдача JWT
    GET /api/v1/auth/me текущий пользователь
    POST /api/v1/auth/change-password смена пароля

    Для Swagger нужно нажать Authorize. В поле username вводится email пользователя, в password - пароль, client_id и client_secret оставляются пустыми.

    Пользователи и предметные сущности

    Роутер Endpoint-группа
    users.py /api/v1/users/ и /api/v1/users/{user_id}
    categories.py /api/v1/categories/ и /api/v1/categories/{category_id}
    tasks.py /api/v1/tasks/, связи с категориями
    time_entries.py /api/v1/time-entries/
    daily_plans.py /api/v1/daily-plans/ и элементы планов
    reminders.py /api/v1/reminders/
    parser.py синхронный парсинг и очередь

    Каждая CRUD-группа содержит GET списка, POST создания, GET одной записи, PATCH обновления и DELETE удаления. Для задач и планов отдельно реализованы endpoint управления ассоциативными сущностями.

    Сервисный слой

    Роутеры отвечают за HTTP-контракт, а бизнес-логика вынесена в app/services/:

    • auth.py - поиск пользователя, проверка пароля, регистрация, JWT и смена пароля;
    • users.py - CRUD пользователей;
    • categories.py - CRUD категорий;
    • tasks.py - CRUD задач и связей TaskCategory;
    • time_entries.py - CRUD времени и вычисление минут по интервалу;
    • daily_plans.py - CRUD планов и элементов;
    • reminders.py - CRUD напоминаний;
    • parser_client.py - HTTP-клиент к parser-service;
    • utils.py - общие операции get_or_404, partial update и commit/refresh.

    Например, services/tasks.py перед созданием задачи проверяет владельца, после создания загружает владельца, категории, записи времени и напоминания, поэтому response содержит вложенные связанные модели.

    JWT и безопасность

    Файл app/core/security.py содержит:

    1. hash_password() - хэширование через pwdlib;
    2. verify_password() - проверку пароля;
    3. create_access_token() - JWT с sub=email и exp;
    4. decode_token() - проверку подписи и срока действия;
    5. get_current_user() - извлечение пользователя из JWT;
    6. get_current_active_user() - проверку is_active.

    Открытый пароль в базе не хранится: в users.hashed_password лежит только хэш.

    Миграции

    Начальная схема создаётся в migrations/versions/20260416_0001_initial_schema.py. Миграция 20260416_0002_add_user_password_hash.py добавляет поле для хэшированного пароля.

    В Docker перед стартом Uvicorn выполняется:

    alembic upgrade head

    Это гарантирует, что база обновлена до последней версии схемы.

    Проверка

    Проверены регистрация пользователя, логин, GET /auth/me, создание категории и задачи, связь задачи с категорией, запись времени, ежедневный план, элемент плана и напоминание. Все операции вернули ожидаемые HTTP-коды 2xx, а вложенные связи присутствовали в ответах.
